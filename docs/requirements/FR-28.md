# FR-28. «Разослать» итог

Приоритет: **Must** · Этап: **1** · Модуль: пробелы и закрытие

## Требование (SRS v3)
«Разослать» доступно всегда. Если остались пробелы — подтверждение с их числом; пункты без исполнителя идут по BR-4.

## Критерии приёмки
1. Остались 2 пробела → система спрашивает «Осталось 2 пробела», после согласия рассылает; рассылка не блокируется (AC-1.7). В API — поле `confirm_open_gaps` (OQ-03).
2. `POST /meetings/{id}/send` → встреча `sent`, `summary_sent_at` заполнен.
3. Пункт draft с `accepted_in_meeting` → `accepted`, `sent_at`, `accepted_at`; DUE_TOMORROW создаётся (BR-8).
4. Пункт draft без отметки с исполнителем → `pending`, `sent_at`; ссылка исполнителю; CONFIRM_REQUEST; планируется CONFIRM_REPEAT (BR-10); DUE_TOMORROW (BR-8).
5. Пункт без исполнителя → `pending` без ссылки, в итоге с пометкой «не назначен» (BR-4).
6. SUMMARY уходит всем участникам встречи не позже 5 минут; свои пункты получателя сверху (AC-3.1). Кому именно — OQ-12.
7. Повторное «Разослать» не создаёт новых писем (BR-5, уникальный dedupe_key).
8. Пишется событие `summary_sent` с props `items_total`, `items_with_open_gaps`, `recipients`.
9. Все изменения статусов, `item_events`, события аналитики и строки `notifications` — в одной транзакции.

## Правила и данные
- **BR-4.** Пункт без исполнителя при рассылке идёт в итог с пометкой «не назначен», получает статус pending без ссылки и первым попадает в сверку следующей встречи.
- **BR-5.** Рассылка идемпотентна: повторное нажатие не создаёт новых писем (dedupe_key = meeting_id:type:recipient). Пункт, добавленный после рассылки, уходит отдельным CONFIRM_REQUEST.
- **BR-8.** DUE_TOMORROW создаётся при рассылке пункта со сроком. Если до срока меньше одного рабочего дня, напоминание не создаётся.
