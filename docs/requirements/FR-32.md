# FR-32. Действия по ссылке только POST с CSRF

Приоритет: **Must** · Этап: **1** · Модуль: подтверждение по ссылке

## Требование (SRS v3)
Действия по ссылке — только POST с CSRF-токеном страницы; GET ничего не меняет (BR-12).

## Критерии приёмки
1. `GET /p/{token}` (в том числе многократный, как от почтового сканера) не меняет статус пунктов, сроки, `notifications` (AC-3.3).
2. `POST /p/{token}/items/{id}/{action}` без CSRF-токена или с неверным → отказ, пункт не меняется → 403 `CSRF_INVALID`.
3. CSRF-токен выдаётся страницей (`GET /p/{token}`, поле `csrf_token`) вместе с cookie `csrf_token` (`HttpOnly; SameSite=Strict; Path=/api/v1/p`); POST шлёт его в заголовке `X-CSRF-Token` (double submit).
4. Кнопка из письма открывает страницу с уже выбранным действием и кнопкой подтверждения; само открытие ничего не меняет.
5. Запрос на путь действия любым методом, кроме POST, не меняет состояние.

## Правила и данные
- **BR-12.** GET по ссылке никогда не меняет состояние: почтовые сканеры открывают ссылки сами. Кнопка в письме ведёт на страницу, действие подтверждается POST.
