# FR-21. Размытые формулировки и готовый вопрос (LLM)

Приоритет: **Must** · Этап: **2** · Модуль: пробелы и закрытие

## Требование (SRS v3)
Размытые формулировки ищет LLM; к каждому пробелу — готовый вопрос ведущему до 120 символов.

## Критерии приёмки
1. LLM вернула `vague_action: true` и `question` → открыт пробел `vague_action` с `source = llm` и этим вопросом.
2. `question` длиннее 120 символов → вопрос отброшен, используется вопрос по умолчанию «Что будет результатом?».
3. LLM вернула `vague_action: false`, а словарь глаголов пробел нашёл → решение — OQ-09 (LLM только дополняет правила).
4. LLM недоступна или таймаут 8 с → пробел `vague_action` ищется по словарю глаголов (этап 1), вопрос по умолчанию; сценарий не падает (AC-1.8).
5. Пример: «Иван разберётся с выгрузкой к пятнице» → вопрос вида «Иван, что будет результатом к пятнице — файл выгрузки или план?».
6. Событие `gap_detected` с `source = llm`.
7. Вызов пишется в `llm_calls` (task = `gaps` или `question`), не в `analytics_events`.

## Правила и данные
- Контракт LLM и проверки ответа — [FR-12](FR-12.md).
- **BR-15.** LLM заполняет только пустые поля и никогда не трогает поля из items.manual_fields.
- **BR-21.** Во внешнюю LLM уходят строка решения, дата и участники в виде id и имени без фамилии.
- Тип «нет критерия готовности» в SRS отсутствует — OQ-09.
