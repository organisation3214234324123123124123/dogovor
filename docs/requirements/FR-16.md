# FR-16. Правка пункта после рассылки

Приоритет: **Must** · Этап: **1** · Модуль: панель встречи · Решение 23.10

## Требование (SRS v3)
После рассылки ведущий может править «что», срок и «готово»; исполнитель меняется только через «Переназначить». О правке исполнитель получает одно письмо ITEM_CHANGED «было → стало»; несколько правок до отправки объединяются (BR-16).

## Критерии приёмки
1. Пункт в pending / accepted / disputed: `PATCH /items/{id}` (If-Match) с новым `what` → `version + 1`, статус не меняется, создаётся ITEM_CHANGED исполнителю «было → стало» со ссылкой на пункт.
2. Смена срока → `reschedule_count + 1`, DUE_TOMORROW перепланируется (BR-8), срок ссылки пересчитывается (BR-18).
3. Новый срок раньше сегодня → 422 `DUE_IN_PAST`.
4. Смена исполнителя через PATCH после рассылки → 422 `USE_REASSIGN` (в статусах pending, accepted, disputed; снятие исполнителя тоже); менять только через `POST /items/{id}/actions` `reassign`.
5. Две правки подряд до отправки письма → исполнитель получает одно письмо (BR-16).
6. Пункт в done или cancelled → 409 `INVALID_TRANSITION`.
7. Пункт без исполнителя → правка проходит, письма нет.
8. Каждая правка пишет `item_events` (без текста, BR-19) и событие аналитики в той же транзакции.

## Правила и данные
- Переход: pending, accepted, disputed → тот же | правка «что», срока или «готово» | Ведущий | version + 1; при смене срока reschedule_count + 1 и напоминание перепланируется; исполнителю ITEM_CHANGED.
- ITEM_CHANGED: dedupe_key `item:ITEM_CHANGED:version`.
- **BR-16.** Письма одного типа одному получателю в одном запуске воркера уходят одним письмом. В момент отправки условие проверяется снова: закрытый пункт письма не получает.
