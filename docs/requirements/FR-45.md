# FR-45. Карточка пункта

Приоритет: **Must** · Этап: **1** · Модуль: между встречами и сверка

## Требование (SRS v3)
Карточка пункта в кабинете: поля, статус, последний ответ исполнителя (новый срок или «не моё» с комментарием) и история изменений из item_events: кто, что, когда. Открывается из панели, сверки, истории серии и по ссылке из письма HOST_RESPONSE. Действия: «Перенести», «Переназначить», «Снять», правка по FR-16. Видит только ведущий — владелец серии; участникам история не показывается.

## Критерии приёмки
1. `GET /items/{id}` ведущим-владельцем → поля, статус, `is_overdue`, последний ответ исполнителя (новый срок или «не моё» с комментарием из `item_comments`).
2. `GET /items/{id}/history` → записи `item_events`: кто (actor_type и actor), что (action, data), когда (created_at), по времени.
3. Другой ведущий → 404 `NOT_FOUND` на оба запроса (NFR-09).
4. Без сессии → 401; по ссылке исполнителя (`/p/...`) история недоступна.
5. Кнопка из HOST_RESPONSE ведёт на карточку этого пункта (после входа).
6. Действия: `reschedule`, `reassign`, `cancel` через `POST /items/{id}/actions` (FR-43); правка — `PATCH /items/{id}` (FR-16); `reopen` — Should, этап 2.
7. В `item_events.data` нет текста пунктов, имён и комментариев (BR-19).

## Правила и данные
- `item_events`: id bigserial, item_id, actor_type enum(host, assignee, system, tracker), actor_user_id, actor_person_id, action enum, data jsonb, created_at. Только INSERT: у роли приложения нет прав UPDATE и DELETE.
- `item_comments`: id, item_id, author_person_id, kind enum(not_mine, reschedule), text varchar(500), created_at, anonymized_at.
- **BR-19.** Журнал только на вставку. В data — только id, статусы и даты. Свободный текст хранится в item_comments.
