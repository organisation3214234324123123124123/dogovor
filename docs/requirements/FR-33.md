# FR-33. Повторное письмо CONFIRM_REPEAT

Приоритет: **Must** · Этап: **1** · Модуль: подтверждение по ссылке

## Требование (SRS v3)
Нет ответа за 1 рабочий день — одно повторное письмо CONFIRM_REPEAT.

## Критерии приёмки
1. Рассылка во вторник 15:00 (пояс серии), пункт остался `pending` → в среду 15:00 уходит CONFIRM_REPEAT.
2. Рассылка в пятницу → CONFIRM_REPEAT в понедельник (BR-7).
3. В письме только неподтверждённые пункты получателя по этой встрече.
4. Все пункты получателя уже не в pending (принял, сменил срок, «не моё», снят) → письмо не уходит (`cancelled`), даже если строка уже создана (BR-16).
5. Уходит ровно одно повторное письмо; дальше писем о подтверждении нет, пункт попадёт в сверку (AC-3.7).
6. «Принимаю» до срока повтора → повтор отменяется (AC-3.4).
7. dedupe_key `meeting:CONFIRM_REPEAT:person` уникален.
8. Повтор есть и у нового исполнителя после «Переназначить» (FR-43 п.4): один на переназначение, со своим ключом, не создаётся при уже стоящем неотправленном повторе по этой встрече.

## Правила и данные
- **BR-10.** CONFIRM_REPEAT уходит один раз через 1 рабочий день после первого письма, если хотя бы один пункт получателя по этой встрече всё ещё в pending.
- **BR-7.** Рабочие дни — понедельник–пятница по поясу серии. Функция add_business_days(date, n); производственный календарь РФ подключается позже без смены её интерфейса.
- `notifications.scheduled_for` считает бэкенд в UTC по поясу серии; Celery Beat отправляет наступившие.
