# FR-05. Состав серии

Приоритет: **Must** · Этап: **1** · Модуль: аккаунт и серии

## Требование (SRS v3)
Состав серии: имя, e-mail и сторона каждого участника. Человек с тем же e-mail у ведущего один на все серии (`UNIQUE(owner_user_id, email)` в `persons`). Сторона задаётся через `organizations`: у ведущего ровно одна организация с `is_own = true` (своя сторона), остальные внешние.

## Критерии приёмки
1. `POST /series/{id}/members` с именем, e-mail и стороной нового человека → создан `persons`, добавлена строка `series_members`.
2. Тот же e-mail (в любом регистре) у того же ведущего в другой серии → используется существующий `persons`, дубля нет.
3. Тот же e-mail у другого ведущего → отдельная запись `persons` (люди не общие между ведущими).
4. Повторное добавление человека в ту же серию не создаёт второй строки `series_members` (PK(series_id, person_id)).
5. `GET /series/{id}/members` → имя, e-mail, сторона (своя / внешняя организация) каждого участника.
6. `DELETE /series/{id}/members/{personId}` убирает человека из состава; его пункты не меняются (FR-09).
7. Некорректный e-mail или имя длиннее 200 символов → 422 `VALIDATION_ERROR`.
8. Серия другого ведущего → 404 `NOT_FOUND`.
9. Нового человека можно добавить в состав прямо из панели встречи (BR-1); он становится доступен как исполнитель.

## Правила и данные
- **BR-1.** Исполнителем может быть только участник серии. Нового человека ведущий сначала добавляет в состав — прямо из панели.
- `persons`: id, owner_user_id, organization_id → organizations, full_name varchar(200), email citext, anonymized_at, created_at. UNIQUE(owner_user_id, email).
- `organizations`: id, owner_user_id, name varchar(200), is_own bool = false. UNIQUE(owner_user_id, lower(name)); у ведущего ровно одна is_own = true.
- Как в API передаётся сторона и когда создаётся своя организация — OQ-07.
