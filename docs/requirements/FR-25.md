# FR-25. «Согласовано на встрече»

Приоритет: **Must** · Этап: **1** · Модуль: пробелы и закрытие

## Требование (SRS v3)
«Согласовано на встрече» доступно для пункта присутствующего исполнителя со сроком-датой (BR-3).

## Критерии приёмки
1. Исполнитель присутствует, есть due_date, нет открытых `no_assignee`, `no_due`, `due_vague`, `due_past` → `POST /items/{id}/accept-in-meeting` → `accepted_in_meeting = true`, статус остаётся `draft` до рассылки (AC-2.1).
2. Пишется событие `accepted_in_meeting` с props `due_changed`.
3. Исполнитель отмечен отсутствующим → отказ 422 (код — OQ-06); в интерфейсе кнопка неактивна с причиной (AC-2.2).
4. Нет due_date (пусто или только due_text) → 422 `GAPS_OPEN` или `VALIDATION_ERROR` (OQ-06); кнопка неактивна с причиной.
5. Открыт только `vague_action` → отметка ставится (пробел не блокирует).
6. После рассылки такой пункт уходит в `accepted` с `accepted_at` (FR-28) и получает ссылку (FR-35).
7. Смена даты до рассылки → в итог уходит новая дата, reschedule_count не растёт (AC-2.4).
8. Тело `{"value": bool}`: `true` ставит отметку, `false` снимает (OQ-10); смена исполнителя отметку сбрасывает.

## Правила и данные
- **BR-3.** «Согласовано на встрече» ставится, только если исполнитель присутствует, есть due_date и нет открытых пробелов no_assignee, no_due, due_vague, due_past. Пробел vague_action не блокирует — решает ведущий.
- `items.accepted_in_meeting bool = false`.
