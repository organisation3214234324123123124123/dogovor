# Нефункциональные требования, которые влияют на код

Источник: SRS v3, раздел «Нефункциональные требования». Значения рассчитаны на пилот: до 50 ведущих и до 10 одновременных встреч.
Не вошли: NFR-04 (звук, этап 3), NFR-07 (доступность 99% и бэкапы — эксплуатация).

| ID | Требование | Как проверяем | FR |
| --- | --- | --- | --- |
| NFR-01 | Пробел по правилам появляется в панели не позже 500 мс после ввода строки (p95) | Нагрузочный тест Locust | FR-10, FR-20 |
| NFR-02 | Ответ LLM: p95 не дольше 3 с, таймаут 8 с; без LLM панель работает на правилах | llm_calls; тест с выключенным LLM | FR-12, FR-21 |
| NFR-03 | p95 ответа API не больше 300 мс при 20 запросах в секунду (без LLM) | Нагрузочный тест | все |
| NFR-05 | WebSocket переподключается за 5 с и догружает пропущенные изменения | E2E-тест с обрывом сети | FR-14 |
| NFR-06 | Немедленные письма (SUMMARY, HOST_RESPONSE) уходят не позже 5 минут; падение воркера не теряет письма, два воркера не шлют одно письмо (перед отправкой воркер проверяет статус письма в notifications) | sent_at − created_at; тест с двумя воркерами | FR-28, FR-34 |
| NFR-08 | Пароли — Argon2id; весь трафик — TLS 1.2+; секреты только в переменных окружения | Ревью; сканер секретов в CI | FR-01 |
| NFR-09 | Каждый запрос ведущего фильтруется по owner_user_id. Чужой объект всегда даёт 404, а не 403 | Тест: второй ведущий получает 404 на любой объект первого | все ручки кабинета |
| NFR-10 | 30 запросов в минуту на IP для /p (limit_req в nginx); 60 решений в минуту на встречу. Превышение — 429 RATE_LIMITED с Retry-After | Скрипт получает 429 | FR-10, FR-31 |
| NFR-11 | JSON-логи с request_id; /health — состояние БД, очередь писем, доступность LLM, время последнего запуска воркера | Проверка на стенде | — |
| NFR-12 | ПДн (152-ФЗ): база и бэкапы в РФ; LLM с обработкой в РФ по договору поручения (BR-21). ПДн — имя и e-mail; согласие ведущего при регистрации; обезличивание не позднее 10 рабочих дней | Чек-лист перед пилотом | FR-01, FR-52 |
| NFR-13 | Текст пунктов, расшифровки и запросов к LLM не пишется в логи; e-mail маскируется (i***@alfa.ru); токены не пишутся | Проверка логов после E2E | все |
| NFR-14 | Кабинет: две последние версии Chrome, Яндекс Браузера, Firefox, Safari; адаптивная вёрстка от 360 px. Страница по ссылке: от 320 px, iOS Safari и Android Chrome | Ручная проверка | фронтенд |
| NFR-15 | Письма корректно отображаются в Outlook, Яндекс Почте, Mail.ru и Gmail; HTML и text/plain с теми же ссылками | Тестовые рассылки на ящики команды | письма |
| NFR-16 | Страница по ссылке — WCAG 2.1 AA: контраст не ниже 4,5:1, кнопки не меньше 44×44 px, работа с клавиатуры | axe-core в CI | FR-31 |
| NFR-17 | Покрытие тестами правил пробелов, переходов и планировщика писем — не ниже 90%, всего кода — не ниже 70%. Миграции — Alembic; промпты в базе (llm_prompts) с номером версии, стартовая версия — миграцией; каждый вызов пишет версию промпта в llm_calls | Отчёт покрытия в CI | FR-12, FR-20 |
| NFR-18 | Вся система поднимается командой docker compose up с демо-данными. Первая сборка на чистой машине — не дольше 10 минут, повторный запуск — секунды | Проверка на чистой машине | — |

Дополнительно из SRS: в демо- и тестовых данных только адреса команды (письма всегда идут через Postbox, локальной почты нет).
