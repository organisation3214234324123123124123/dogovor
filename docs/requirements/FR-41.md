# FR-41. Просроченный пункт попадает в сверку

Приоритет: **Must** · Этап: **1** · Модуль: между встречами и сверка

## Требование (SRS v3)
Пункт без отметки после срока становится просроченным и попадает в сверку; писем о просрочке нет.

## Критерии приёмки
1. Пункт в accepted, due_date = вчера (пояс серии) → `is_overdue = true` (AC-4.2).
2. Пункт в pending с прошедшим сроком → `is_overdue = true`.
3. done, cancelled, disputed, draft с прошедшим сроком → `is_overdue = false`.
4. due_date = сегодня → не просрочен.
5. Статус пункта при просрочке не меняется: это вычисляемый признак, не статус.
6. Писем о просрочке нет: в `notifications` ничего не создаётся.
7. Ежедневно в 00:05 по поясу серии для каждого просроченного пункта пишется `item_overdue` с props `days_overdue`.
8. Просроченный пункт показывается в сверке следующей встречи (FR-42).

## Правила и данные
- `is_overdue = due_date < сегодня в часовом поясе серии AND status IN (pending, accepted)`.
- Частичный INDEX(due_date) WHERE status IN (pending, accepted).
