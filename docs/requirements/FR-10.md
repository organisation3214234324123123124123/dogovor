# FR-10. Ввод решения строкой

Приоритет: **Must** · Этап: **1** · Модуль: панель встречи

## Требование (SRS v3)
Решение вводится одной строкой до 1000 символов. Пункт в draft появляется сразу, разбор идёт в фоне.

## Критерии приёмки
1. `POST /meetings/{id}/items` с `raw_text` = «Иван разберётся с выгрузкой к пятнице» → 201, пункт со `status = draft`, `source = manual`, `version = 1`, `raw_text` сохранён.
2. raw_text ровно 1000 символов → принят; 1001 символ или пустой → 422 `VALIDATION_ERROR`.
3. Пункт сразу приходит в панель событием `item.created` по WebSocket (FR-14).
4. Поля «что / кто / срок» заполняются разбором (FR-11, на этапе 2 ещё FR-12) и приходят событием `item.updated`.
5. Пробел по правилам появляется в панели не позже 500 мс после ввода строки, p95 (NFR-01).
6. Больше 60 решений в минуту на одну встречу → 429 `RATE_LIMITED` с `Retry-After` (NFR-10).
7. Пишется событие `decision_captured` с props `source` (manual), `fields_filled`.
8. Встреча другого ведущего → 404. Добавлять можно во встречу в `live`, `closing` и `sent` (BR-5, OQ-02): после рассылки пункт создаётся в draft и уходит повторным «Разослать», которое берёт только новые draft-пункты. Встреча в `planned` → 409 `MEETING_NOT_LIVE`.
9. Текст решения не пишется в логи (NFR-13).

## Правила и данные
- `items`: raw_text varchar(1000), what varchar(500), assignee_person_id, due_date, due_text varchar(100), done_criteria varchar(500), manual_fields text[], source enum(manual, asr), status, version int = 1 и др. — см. [data-model.md](data-model.md).
- Пример: `{"raw_text": "Иван разберётся с выгрузкой к пятнице", "what": "Разобраться с выгрузкой", "assignee_person_id": "p_12", "due_date": "2026-10-16", "due_text": "к пятнице", "done_criteria": null, "source": "manual", "status": "draft"}`.
