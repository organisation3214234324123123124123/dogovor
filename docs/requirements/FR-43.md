# FR-43. Действия на сверке

Приоритет: **Must** · Этап: **1** · Модуль: между встречами и сверка

## Требование (SRS v3)
Действия на сверке: «Сделано», «Перенести», «Снять», «Переназначить» (для pending, accepted и disputed). Сверку можно пропустить. Отдельного итога после сверки нет: результат видят все на экране, исполнители получают только письма о своих пунктах (ITEM_CHANGED, ITEM_REASSIGNED).

## Критерии приёмки
`POST /items/{id}/actions` с `If-Match`:
1. `done` из pending/accepted → `done`, `done_at`, `done_by = host`; напоминание отменено; `item_done` (on_time, by). Из disputed → 409 `INVALID_TRANSITION`.
2. `reschedule` с датой из pending/accepted → новый due_date, `reschedule_count + 1`, напоминание перепланировано, исполнителю ITEM_CHANGED. Дата раньше сегодня → 422 `DUE_IN_PAST` (AC-4.5).
3. `cancel` из pending/accepted/disputed → `cancelled`, `cancelled_at`, напоминание отменено, писем нет.
4. `reassign` с person_id из pending/accepted/disputed → `pending` у нового исполнителя; ему ссылка и CONFIRM_REQUEST, а через 1 рабочий день (BR-7) один CONFIRM_REPEAT, если пункт всё ещё в pending (BR-10, FR-33); если у него по этой встрече уже стоит неотправленный CONFIRM_REPEAT, второй не создаётся; прежнему ITEM_REASSIGNED без ссылки и без имени нового; прежняя ссылка больше не показывает пункт.
5. `reassign` на человека не из состава серии → 422 `NOT_A_PARTICIPANT` (BR-1).
6. Любое действие из недопустимого статуса → 409 `INVALID_TRANSITION`; устаревший If-Match → 409 `VERSION_CONFLICT`.
7. Каждое действие на сверке пишет `review_action` (action: done, reschedule, cancel, reassign), строку `item_events` — в одной транзакции.
8. «Пропустить» → пункты остаются открытыми и покажутся на следующей встрече; пишется `review_skipped` (AC-4.6). Ручка `POST /meetings/{id}/review/skip` → 204 (OQ-07).
9. Итогового письма после сверки нет.

## Правила и данные
- **BR-1.** Исполнителем может быть только участник серии.
- **BR-8.** DUE_TOMORROW перепланируется при смене срока и отменяется при done и cancelled.
