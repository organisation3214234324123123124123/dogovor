# Решения

Журнал принятых решений: дата, решение, причина.

| Дата | Решение | Почему |
|---|---|---|
| 2026-10-23 | Стек: FastAPI, SQLAlchemy 2, Alembic, Celery, PostgreSQL 16; фронтенд (React + Vite + TS) живёт отдельно | Зафиксирован в ТЗ |
| 2026-10-23 | Sync SQLAlchemy, не async | Проще отладка и тесты, общий код для API и Celery, нагрузка небольшая |
| 2026-10-23 | Слои router -> service -> repository, как описано в [architecture.md](architecture.md) | Так в ТЗ (SRS); каждый слой тестируется отдельно |
| 2026-10-23 | Реестр образов GHCR | Рядом с кодом, авторизация через `GITHUB_TOKEN` |
| 2026-10-23 | Заглушки LLM и Postbox, пока нет ключей | Разработка не ждёт ключей; код один, ключ включает реальный клиент |
| 2026-10-24 | Пароли: pwdlib + argon2 | Современный стандарт хеширования, без устаревшего passlib |
| 2026-10-24 | Вход: PyJWT в httpOnly-cookie `session` (SameSite=Lax, 7 дней), токена в теле `/auth/login` нет; `/auth/token` и `Authorization: Bearer` — служебный вход Swagger, только в режиме разработки | Как в контракте аналитиков; стандартные библиотеки вместо самописных; Bearer на сервере расширяет поверхность атаки, а Swagger получает доступ к закрытым ручкам без их открытия на сервере |
| 2026-10-24 | Конфликт правок пункта — 409 `VERSION_CONFLICT`, без If-Match — 428 | Так в SRS |
| 2026-10-24 | `/admin/*` — отдельная схема `X-Admin-Token` = `ADMIN_TOKEN` (пусто — 403); сессия ведущего там не действует | Служебный доступ не должен открываться обычным входом; без новой таблицы ролей |
| 2026-10-24 | Коды ошибок — одна таблица в `docs/requirements/api.md`; openapi, FR и OQ ссылаются на неё | Коды в разных документах расходились |
| 2026-10-24 | У писем, которые законно повторяются, `dedupe_key` получает различитель (версия пункта или id события) | Форматы SRS теряют повторные письма (OQ-16) |
| 2026-10-24 | Журнал `item_events`: прямой DELETE запрещён триггером, удаление только каскадом с пунктом | FR-15 удаляет draft физически, а журнал не должен правиться вручную (OQ-17) |
| 2026-10-24 | Падеж имён в `items/parsing.py` — окончания по правилам, без pymorphy3; срок — регулярные выражения | Нет новой зависимости и словарей; для имён из состава серии точности хватает (FR-11) |
| 2026-10-24 | Лимит 60 решений в минуту на встречу (NFR-10) считается по строкам пунктов в БД под блокировкой встречи | Счётчик в памяти не работал бы на нескольких воркерах, Redis для этого не нужен |
| 2026-10-24 | События живой панели уходят после commit: `live.service.publish_after_commit` держит очередь в сессии и сбрасывает её при откате | Подписчик не должен увидеть кадр отменённой транзакции |
| 2026-10-24 | Сверка (FR-42): пункт показывается один раз, в первой подходящей группе: unassigned, overdue, disputed, stale_pending | Порядок из OQ-13; без дублей на экране |
| 2026-10-24 | «Висит без ответа» в сверке — 2 рабочих дня и больше от `sent_at` | Счёт дней из OQ-13 |
| 2026-10-24 | `item_overdue` пишется по дню серии: просрочены пункты с `due` раньше сегодняшнего дня, Beat проверяет раз в 5 минут | Согласованность с `is_overdue` в API; дубли отсекает дедуп по дню |
| 2026-10-24 | «Переназначить» ставит CONFIRM_REQUEST без токена в `payload`; ссылку выпускает отправитель писем в момент отправки (FR-30) | Сырой токен не хранится в БД; без `sent_at` пункт сразу считался бы «без ответа» |
| 2026-10-24 | `PATCH /agenda/{id}` с `position` — обычная перестановка: повестка перенумеровывается 1..n, позиция ограничивается без ошибки | Согласовано в команде (FR-27 п.1, 5) |
| 2026-10-24 | `agenda_item_uncovered` пишется один раз — при первом переходе из open в covered/moved, если к пункту не привязано решение | Событие не должно дублироваться при повторных правках (FR-27) |
| 2026-10-24 | FR-02: неудачные входы хранятся в `login_attempts` (БД, не Redis), блокировка на 15 минут от 10-й неудачи; параллельные попытки сериализует блокировка по e-mail | Работает со временем из тестов и без Redis (OQ-11) |
| 2026-10-24 | Неудачный вход сохраняется даже при ответе 401: `AppError.keep_changes` заставляет `get_db` сделать commit | Откат на 401 теряет счётчик, и блокировку можно обойти |
| 2026-10-24 | FR-03: токены сброса пароля хранятся в `password_reset_tokens` как SHA-256; не больше 3 писем на e-mail в час | Сырой токен есть только в письме (FR-03) |
| 2026-10-24 | FR-14: транспорт событий живой панели выбирает настройка `live_bus` (`memory` или `redis`); очередь подписчика 100, догрузки `?since=` нет | В тестах работает без Redis; клиент перечитывает `GET /meetings/{id}` (OQ-07) |
| 2026-10-24 | WebSocket: Origin вне `cors_origins` закрывается кодом 4403, истёкший токен — 4401 | Защита от cross-site WebSocket |
| 2026-10-24 | LLM (FR-12, FR-21): `parse_text` и `enrich_item` принимают `LLMClient` аргументом; общий дедлайн на разбор, ошибка провайдера пишется в `llm_calls` | Клиент подменяется в тестах; один вызов `parse` вместо отдельных gaps/question (OQ-18) |
| 2026-10-24 | FR-26: `overload_warning` приходит только в ответе на создание пункта и правку исполнителя, в WS-кадр не попадает | Фронту не нужен второй запрос; порог берётся из серии |
| 2026-10-24 | ITEM_CHANGED сливается только с `queued` строкой того же получателя, взятой `FOR UPDATE SKIP LOCKED` | Письмо, уже забранное отправщиком, менять нельзя |
| 2026-10-24 | Разбор срока: «в пятницу» в пятницу — через неделю, «до пятницы» — сегодня; «на следующей неделе» и «до конца недели» — пятница, «до конца месяца» — последний день месяца | OQ-08 это не задаёт; рабочая неделя заканчивается в пятницу |
| 2026-10-24 | Несуществующая дата («к 31.02») даёт `due_text` без `due_date` (пробел `due_vague`); двузначный год — 20xx | Не подставляем срок, которого человек не называл |
| 2026-10-24 | «Согласовано на встрече» (BR-3) проверяет только открытые блокирующие пробелы и наличие `due_date` | Отклонённый `due_past` — осознанное решение ведущего, оно не должно мешать согласованию |
| 2026-10-24 | День недели с падежом по предлогу: «в/во» + винительный, «к» + дательный, «до» + родительный; «на следующей неделе в среду» — среда следующей недели | Меньше ложных сроков («в среде тестирования» срока не даёт) |
| 2026-10-24 | Если после вырезания имени и срока ничего не осталось, `what` пуст (null) | Строка не дублируется в `what` |
| 2026-10-24 | `DELETE /items/{id}`: сначала If-Match (428 без заголовка, 409 `VERSION_CONFLICT`), затем статус (409 `INVALID_TRANSITION`) | Предсказуемый порядок проверок |
| 2026-10-24 | OQ-08: дата без года, прошедшая больше полугода назад, — следующий год; прошедшая недавно остаётся в текущем и даёт `due_past` | Работает на стыке годов и не ломает «К 20.10 в прошлом» |
| 2026-10-24 | Токен ссылки случайный (`secrets.token_bytes(32)`), в БД только SHA-256; у каждого письма свой токен в `access_link_tokens`, все гаснут вместе со ссылкой | Токен не выводится из `link_id` и не зависит от `SECRET_KEY` (FR-30, NFR-13) |
| 2026-10-24 | Отправщик `send_due` (Beat) забирает строки в `sending`, коммитит каждое письмо отдельно, зависшие возвращает в `queued` | Воркер может упасть посреди отправки; письма не должны теряться или дублироваться (BR-16, NFR-06) |
| 2026-10-24 | Лимит писем (BR-11): сверх лимита письма откладываются на следующий рабочий день и уходят одним; при сбое отправка повторяется с нарастающей паузой (BR-17) | Не заспамить исполнителя, но и не потерять письмо |
| 2026-10-24 | Отправщик перед письмом проверяет, что строка всё ещё его (`UPDATE … WHERE status='sending' AND claimed_at=:метка`) | Иначе параллельное назначение или повторная отправка после возврата зависших строк дали бы дубли |
| 2026-10-24 | Рассылка не повышает `items.version`; ответ исполнителя по ссылке повышает | Ключ CONFIRM_REQUEST остаётся версией до рассылки (FR-32 п.4, OQ-14) |
| 2026-10-24 | Ссылки писем: `/p/<token>?action=<a>&n=<ТИП>`, `n` попадает в `link_opened`; без `n` — SUMMARY | Видно, из какого письма пришли (FR-32 п.4) |
| 2026-10-24 | Автозакрытие по таймеру (FR-23) делает бэкенд: Beat `open_closures` раз в минуту; «Ещё 5 минут» — PATCH `planned_end` | Закрытие не зависит от открытой вкладки ведущего |
| 2026-10-24 | Связь повестки с решениями (задача LLM `agenda`) идёт отдельной Celery-задачей после commit закрытия; чужие id отбрасываются, связь ведущего не перезаписывается | Закрытие встречи не ждёт LLM; по готовности уходит кадр `agenda.updated` (FR-27, OQ-15) |
| 2026-10-24 | `POST /meetings/{id}/send` доступен и из `live`, только `planned` даёт 409 `MEETING_NOT_LIVE` | FR-28: «Разослать доступно всегда» |
| 2026-10-24 | `analytics.track` не бросает исключений: имя вне списка FR-50 — warning и события нет, недопустимое значение prop — warning и prop отбрасывается | Действие пользователя не должно откатываться из-за аналитики |
| 2026-10-24 | В props аналитики допустимы только числа, флаги и короткие коды `[A-Za-z0-9_.-]{1,40}` | В props не должно быть текста (FR-50 п.3) |
| 2026-10-24 | Выгрузка событий: UTC, `date_to` включительно, сортировка `created_at, id`, props — компактный JSON, CSV идёт потоком | Предсказуемая выгрузка (FR-51) |
| 2026-10-24 | Обезличивание нумерует «Участник N» по числу уже обезличенных персон ведущего под `pg_advisory_xact_lock`; повторный вызов ничего не меняет | Параллельные вызовы не должны выдать два одинаковых номера (FR-52) |
| 2026-10-24 | Окно «в срок за 30 дней» (FR-44): сегодня и 29 предыдущих дней | Ровно 30 суток, включая сегодня |
| 2026-10-24 | Чистка BR-20 раз в сутки батчами: старые ссылки, payload писем, аналитика, `llm_calls`, `item_events`, архивные серии и их участники | Сроки хранения персональных данных (BR-20, OQ-17) |
| 2026-10-24 | Отдельной роли БД для чистки нет: миграция 0006 разрешает DELETE в `item_events` при `app.retention_cleanup = on`, задача ставит флаг в своей транзакции | Одна роль БД проще в docker compose |
| 2026-10-24 | Архивная серия отвечает 409 `SERIES_ARCHIVED` на любые правки: пункты, повестка, пробелы, участники, встреча, действия ведущего | Архив — только чтение (FR-09, api.md) |
| 2026-10-24 | Архивировать при идущей встрече нельзя (409 `MEETING_ALREADY_LIVE`); повторное архивирование — 200, `archived_at` не сдвигается | Дата архивации задаёт сроки хранения (BR-20) |
| 2026-10-24 | Образ бэкенда для `main` собирается только после зелёного CI (`release.yml` по `workflow_run`); образ по тегу `v*` собирается по push тега, отдельной проверки CI в `release.yml` нет | Публикация образа в GHCR отделена от CI и запускается событиями `workflow_run` и push тега |
| 2026-10-24 | Расхождения с контрактом API аналитиков (`openapi-v2`) перечислены в разделе «Расхождения с контрактом аналитиков» [api.md](requirements/api.md) | Расхождения, меняющие поведение или фронт, согласуются с аналитиками |
| 2026-10-24 | Журнал запросов маскирует токен в `path` (`/p/<token>` -> `/p/***`, `mask_link_token` в `core/logging.py`) | Токен ссылки исполнителя не должен попадать в журналы (NFR-13) |
| 2026-10-24 | Сессия БД (`SessionDep`, `get_current_user`) объявлена `Depends(get_db, scope="function")` | Commit идёт до ответа 201, а ошибка commit уходит в обработчики как 5xx, а не клиенту успехом |
| 2026-10-24 | Потоковый ответ, читающий БД при отправке (экспорт events.csv), берёт `StreamSessionDep` (`scope="request"`) | Сессия должна жить до конца стрима |
| 2026-10-24 | Необработанное исключение отдаёт 500 `application/problem+json` с `code=INTERNAL_ERROR` без текста ошибки | Контракт: любая ошибка — problem+json |
| 2026-10-24 | Повтор подтверждения новому исполнителю после «Переназначить»: CONFIRM_REPEAT через 1 рабочий день, не больше одного неотправленного на человека и встречу (FR-43 п.4, BR-10) | Переназначенный пункт не должен ждать сверки без напоминания, письма не плодятся |
| 2026-10-24 | У прежнего исполнителя запланированный повтор снимается, если pending по встрече не осталось | Человеку не нужно напоминание о пункте, который ему уже не назначен |
| 2026-10-24 | Токен ссылки ищется по SHA-256 в уникальном индексе: сначала `access_link_tokens`, затем `access_links` — два запроса (NFR-13) | Один запрос с OR-JOIN даёт полный перебор таблицы |
| 2026-10-24 | Хеши токенов письма фиксируются (commit) до SMTP, статус `sent` — после | Письмо не должно уйти с нерабочей ссылкой, если воркер упал после отправки |
| 2026-10-24 | Демо-данные грузятся при старте, только если `DEMO_DATA=1`; `ADMIN_TOKEN` по умолчанию пуст | Нет демо-пароля и служебного ключа в боевой конфигурации |
| 2026-10-24 | DDL схемы — `db/schema.sql`, собирается из миграций `db/dump_schema.sh`, CI сверяет его с миграциями | DDL-скрипт нужен для ревью схемы без запуска миграций; источник правды — миграции |
